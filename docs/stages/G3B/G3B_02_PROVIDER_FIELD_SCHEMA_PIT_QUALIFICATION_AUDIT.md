# G3B-02 — Provider / Field / Schema / PIT Qualification Audit

Status: **ACCEPTED / COMPLETE — 2026-09-08; FORMAL ACQUISITION NOT AUTHORIZED**  
Boundary: **AUDIT-ONLY / NON-EMPIRICAL.** No formal universe/history was downloaded, no provider was selected, and no relationship, abnormality, mechanism, target, return or PnL was computed.

Governance: `G3A evaluates feasibility, not desirability`; G3B-02 evaluates source-contract suitability, not model quality. `leading canonical candidate class ≠ selected provider`, `acquisition breadth ≠ model-use authorization`, and `stored data ≠ decision-time available data` remain binding.

## Method and evidence boundary

The audit used official product documentation, published schemas and access/licensing descriptions. No endpoint probe was necessary. Public documentation that names a field does not by itself establish historical PIT vintage integrity. A qualification therefore applies only to the documented capability and stated limitations.

Qualification meanings:

- `QUALIFIED CANONICAL CANDIDATE`: documented semantics substantially cover the minimum contract; contracting/licensing may still remain.
- `QUALIFIED WITH LIMITATIONS`: usable candidate branch exists, but a material field, vintage, coverage or schema issue requires resolution.
- `FALLBACK ONLY`: potentially usable only through explicit, scoped, reason-coded substitution with visible provenance.
- `NOT PIT-QUALIFIED`: historical availability/vintage requirements are not defensibly established for event-time use.
- `NOT QUALIFIED`: documented capability fails the logical contract.
- `UNRESOLVED`: documentation is insufficient to classify.

| Candidate class | Strength | Binding limitation | Appropriate contract role |

| Official index publishers | Authoritative index identity and constituent decisions | Announcement/effective/vintage history and redistribution terms need exact contract | Canonical candidate for C07/E03 |
| CNINFO/exchange disclosure portals | Official disclosure provenance | Automated historical schema, first-public timestamp, replacements and stable access not proven | E01 audit candidate only; not yet event-time qualified |
| Tushare | Transparent documented API fields and relatively low acquisition burden | Not venue-authoritative; historical source vintage/revision and some units/effective semantics are not fully documented | Documented fallback candidate; never silent patching |
| CSMAR/RESSET and similar licensed databases | Potentially broad integrated historical coverage | Public pages do not resolve exact field semantics, vintage, license or version behavior | Contract/schema audit candidate; current status unresolved/fallback-only by field |
| Internal manifest/quarantine controls | Deterministic provenance and enforceable access separation | Cannot repair missing source vintage | Canonical governance layer C08 and outcome quarantine |

E01 has not satisfied its PIT qualification condition for event-time acquisition/use and does not block core acquisition: `E01 unavailable ≠ core strategy infeasible`.

No finding selects a provider. Formal acquisition remains locked pending researcher decisions listed in the handback.
